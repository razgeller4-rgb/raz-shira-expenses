# Feature Master Backlog — Expense App

**Owner:** רז · **Product promise:** כל אדם מנהל את כספו במסך אישי; הזוג נפגש רק במסך משק־הבית המשותף.  
**Rule:** `Personal` הוא ה־default אחרי כניסה. `Couple` הוא משטח נפרד, לא פילטר ולא ערבוב נתונים.

## עקרונות מוצר ועיצוב

- מוצר Fintech טכנולוגי, כהה/עמוק עם הדגשות electric-lime, cyan ו־violet; לא "אתר עץ".
- טיפוגרפיה עברית מודרנית: Heebo/Assistant לגוף ו־Manrope/Space Grotesk למספרים ולכותרות.
- Motion פונקציונלי בלבד: מעבר מסך, כניסת מספרים, אישור שמירה, טעינה וחשיפת פרטים—עם `prefers-reduced-motion`.
- מרחבי עבודה: אישי, זוגי, הגדרות; לא בחירת משתמש חופשית מתוך הנתונים.
- כל פעולה כספית: טיוטה → ולידציה → אישור → audit/recovery כאשר נדרש.

## סדר ביצוע מחייב

1. **Foundation:** identity + household + RLS + audit + recovery.
2. **Personal-first:** דשבורד אישי, הוצאות והכנסות אישיות.
3. **Couple:** דשבורד זוגי, הוצאות משותפות והתחשבנות.
4. **Automation:** import inbox וכללי סיווג; חיבורים חיצוניים רק לאחר review.
5. **Scale:** הזמנה לחברים, onboarding, roles, analytics ושחרור production.

## Definition of Done לכל פיצ'ר

- התנהגות, בעלות נתונים ו־DoD כתובים.
- state ריק/טעינה/שגיאה/הצלחה/מובייל קיימים.
- אין עקיפת RLS או כתיבה בלי אישור מתאים.
- בדיקה חיה בדמו; שינוי production רק לאחר Gate עצמאי ואישור רז.
