# כללי הפעלה — תוכנית העיצוב החדשה

מקור התוכנית הוא [תוכנית העל](MASTER_PLAN_TO_FINISHED_APP.md). מסמך זה מגדיר אחריות ותהליך בלבד.

- רז: בעל מוצר, בחירת כיוון ואישור תוכן הדמו. שירה: משתמשת ליבה ואימות נוחות ותהליכים. הסוכן: מחקר, תיעוד, עיצוב, מימוש ובדיקה במסגרת ההרשאה.
- עבודה חדשה מתחילה במשימה בעלת ID, מטרה, היקף, תלות וראיה נדרשת.
- מצבים: INVENTORIED, PROPOSED, DESIGN_REVIEW, DESIGN_READY, IMPLEMENTING, DEMO_VERIFIED, USER_APPROVED, RELEASED, VERIFIED, BLOCKED, SUPERSEDED. אין מעבר לפי טענת סוכן בלבד.
- מחקר קוד מוכיח מבנה מקומי. צילום מוכיח מצב חזותי מסוים. בדיקה חיה מוכיחה תרחיש במועד מסוים. אין החלפה בין סוגי הראיות.
- הסקירה המבוקשת ב־13.09 נעשתה בדפדפן ברוחב מובייל. היא אינה בדיקת אייפון פיזי ואינה אישור לשנות פרודקשן. הוראות בדיקה ישנות אינן סיבה לחזור לכיוון שנדחה.
- הדמו כיום משתמש ב־app_state_demo לפי הקוד. יש להימנע מפעולות שנוגעות בנתונים אמיתיים גם בדמו. שום נתון אמיתי אינו חומר מילוי לעיצוב.
- קידום שינוי לייצור: גיבוי עדכני בר־שחזור, בדיקה בדמו ואישור רז על התוכן לפי כללי הפרויקט. git push רגיל אינו דורש אישור נוסף כאשר העבודה מאושרת; אין force-push או מחיקה הרסנית.
- לפני שינוי נתונים אין להשתמש בפקודה הישנה עם LATEST שאינו קיים. מאתרים גיבוי קיים בפועל ומוודאים תקפות ושחזור; עותק של HTML לבדו אינו גיבוי מסד.
- העברת נתונים, יצירת הרשאות, שירות בתשלום ותלויות חדשות דורשות את בדיקת ההרשאה המתאימה; אין להוסיף אותן כחלק סמוי מעיצוב.
- חותמים כל גל ביומן ובתור העבודה. מסמכי עזר לא מנהלים מצב מקביל.
